# Monopoly Lite: полный учебник по Python, Oracle и PL/SQL

> Цель этого файла — не просто помочь «зазубрить» проект, а дать модель в голове: где живут данные, кто их изменяет, как Python разговаривает с Oracle и как из нажатия кнопки получается новая строка в таблице.

## 1. Самая главная мысль

Проект состоит из трёх слоёв:

1. **Oracle Database** хранит таблицы и сама выполняет правила игры. Это не просто «файл с данными», а отдельный серверный процесс.
2. **Python-клиент** открывает TCP-соединение с Oracle, вызывает PL/SQL-процедуры/функции и превращает ответы Oracle в Python-объекты.
3. **PySide6 GUI** рисует окна, поле, кнопки и таблицы. GUI не должен сам решать, можно ли купить улицу: он просит об этом БД.

Главный поток:

```text
пользователь
  → кнопка PySide6 (app/ui.py)
  → метод GameService (app/service.py)
  → обёртка Database (app/db.py)
  → драйвер python-oracledb
  → Oracle Listener, localhost:1521
  → сервис FREEPDB1
  → схема MONOPOLY
  → PL/SQL-пакет monopoly
  → INSERT/UPDATE/SELECT в таблицах
  → COMMIT
  → ответ и перерисовка GUI
```

Важно: Python не «поднимает» Oracle. Сначала Docker запускает сервер Oracle, и только потом Python к нему подключается.

## 2. Словарь без зауми

- **БД** — организованные данные.
- **СУБД** — программа, управляющая БД; здесь Oracle Database.
- **Схема** Oracle — набор объектов одного владельца. Пользователь `monopoly` владеет таблицами и пакетом.
- **Таблица** — набор строк одного типа; столбцы описывают атрибуты.
- **SQL** — язык создания, чтения и изменения данных.
- **PL/SQL** — процедурное расширение SQL от Oracle: переменные, `IF`, циклы, процедуры, функции, исключения.
- **Транзакция** — набор изменений как единое целое. `COMMIT` фиксирует, `ROLLBACK` отменяет.
- **Курсор** — «ручка» для чтения результа запроса.
- **Индекс** — дополнительная структура быстрого поиска; аналог алфавитного указателя.
- **Триггер** — код, автоматически срабатывающий на событие. **В текущем проекте триггеров нет.**
- **Представление (`VIEW`)** — сохранённый SELECT. **В текущем наборе SQL-файлов VIEW нет.**

## 4. Что и зачем устанавливаем

### Docker и Oracle

Docker — среда запуска контейнеров. Oracle Free Lite живёт в контейне `monopoly-oracle`. Параметр `-p 1521:1521` прокидывает порт компьютера в контейнер. `-v monopoly_oradata:/opt/oracle/oradata` держит данные в томе: остановка/пересоздание контейнера не должно стереть файлы БД.

Oracle Listener слушает порт 1521. `FREEPDB1` — имя сервиса подключаемой pluggable database. `monopoly` — пользователь/схема, а не имя БД.

### Python-зависимости

```text
oracledb==4.0.2       # драйвер Python ↔ Oracle
PySide6==6.11.1       # Qt GUI: окна, кнопки, потоки, таймеры, рисование
python-dotenv==1.2.2  # загрузка KEY=VALUE из .env
```

`venv` изолирует пакеты этого проекта. `pip install -r requirements.txt` скачивает именно зафиксированные версии. `python-oracledb` умеет Thin mode, поэтому в коде нет `init_oracle_client()` и отдельный Oracle Instant Client для этой схемы не требуется.

2. Один раз скачать image Oracle, создать volume и container по командам из `WINDOWS_DEPLOYMENT.md`.

6. Создать `.venv`, активировать, выполнить `pip install -r requirements.txt`.

8. Запустить `python -m app.main`.

Ежедневно уже не нужно заново инсталлировать схему: `docker start monopoly-oracle`, активация `.venv`, `python -m app.main`.

## 6. Как рождается соединение

### Шаг 1. Конфигурация

`load_dotenv()` из `app/config.py` ищет `.env` и добавляет его значения в environment. `os.getenv('ORACLE_USER', 'monopoly')` означает: взять `ORACLE_USER`, а если его нет — `monopoly`.

```python
@dataclass(frozen=True)
class Settings:
    user: str = ...
```

`@dataclass` генерирует конструктор и другую рутину; `frozen=True` запрещает случайно переписать настройку. `settings = Settings()` выполняется при первом import.

### Шаг 2. Точка входа

`python -m app.main` задаёт `__name__ == '__main__'`, поэтому вызывается `main()`. `ui.main()` создаёт `QApplication`, затем `Window()`.

### Шаг 3. Конструктор Window

`Window.__init__` выполняет:

```python
self.db = Database()
self.s = GameService(self.db)
```

Первая строка уже пытается соединиться. Если Oracle не запущен, DSN/пароль неверны или порт недоступен, окно не создастся, а `ui.main()` покажет ошибку.

### Шаг 4. `oracledb.connect`

```python
self.connection = oracledb.connect(
    user=settings.user,
    password=settings.password,
    dsn=settings.dsn,
)
```

DSN `localhost:1521/FREEPDB1` = host `localhost`, port `1521`, service `FREEPDB1`. Драйвер проходит аутентификацию и возвращает `Connection`. Это долгоживущее соединение главного окна.

### Шаг 5. Cursor

Connection — сеанс, Cursor — исполнитель конкретных команд:

```python
@contextmanager
def cursor(self):
    cur = self.connection.cursor()
    try:
        yield cur
    finally:
        cur.close()
```

`@contextmanager` позволяет `with db.cursor() as cur`. `yield` временно отдаёт cursor внутрь `with`; `finally` сработает даже при ошибке. Закрыть cursor — освободить ресурс; это не равно закрыть connection.

### Шаг 6. Закрытие

При закрытии GUI `closeEvent` дожидается background thread, сообщает об отключении и вызывает `self.db.close()`. Это закрывает сетевой сеанс.

## 7. Как появляется новая запись: регистрация

Разберём весь маршрут.

1. `ui.register()` берёт `self.le.text()` и `self.pe.text()`.
2. `GameService.register(l, p)` вызывает:

```python
self.db.callproc('monopoly.register_user', [l, p])
```

3. `Database.callproc` открывает cursor и выполняет `cur.callproc(name, params)`.
4. Oracle находит package `MONOPOLY`, в нём `REGISTER_USER`.
5. PL/SQL проверяет логин/пароль, затем делает:

```sql
INSERT INTO "ПОЛЬЗОВАТЕЛИ" ("ЛОГИН", "ПАРОЛЬ_ХЭШ")
VALUES (TRIM(p_login), STANDARD_HASH(p_password, 'SHA256'));
```

`INSERT INTO` называет таблицу; в скобках указаны целевые столбцы; `VALUES` — значения. ID не передаётся: `IDENTITY` генерирует его. Дата не передаётся: срабатывает `DEFAULT SYSDATE`.

6. Если всё успешно, Python делает `connection.commit()`. Только теперь строка устойчиво сохранена.
7. Если Oracle выдал ошибку, `rollback()` отменяет всю незафиксированную транзакцию, а `DatabaseError` доходит до GUI.

Пароль не хранится открытым текстом, но это простой SHA-256 без salt и адаптивной сложности. Для учебного проекта понятно, для production лучше Argon2/bcrypt/PBKDF2.

## 8. Три способа вызвать Oracle из Python

### Procedure: делает действие

```python
db.callproc('monopoly.buy_property', [participant_id, cell_id])
```

Процедура не имеет `RETURN`, но может иметь `OUT`. `callproc` коммитит успех и откатывает Oracle-ошибку.

### Function: возвращает одно значение

```python
db.callfunc('monopoly.authenticate_user', oracledb.NUMBER, [login, password])
```

Второй аргумент — ожидаемый Oracle-тип результа. `login()` превращает Oracle NUMBER в Python `int`.

### Ref cursor: возвращает табличный результат

```python
rc = cur.callfunc(name, oracledb.DB_TYPE_CURSOR, params)
columns = [x[0].lower() for x in rc.description]
rows = [dict(zip(columns, row)) for row in rc]
```

`description` хранит метаданные столбцов. `zip(columns, row)` сопоставляет имена и значения. Из Oracle-строки `(1, 'Игра')` получается `{'id_игры': 1, 'название': 'Игра'}`.

### OUT-параметр

`create_game` должен вернуть новый ID:

```python
out = cursor.var(oracledb.NUMBER)
result = db.callproc('monopoly.create_game', [u, n, m, password, out])
game_id = result[4].getvalue()
```

В PL/SQL он объявлен `p_game_id OUT NUMBER`, а `INSERT ... RETURNING "ID_ИГРЫ" INTO p_game_id` забирает identity в эту переменную без дополнительного SELECT.

### Bind variables

Прямой SELECT в `participant()`:

```python
c.execute('SELECT ... WHERE "ID_ПОЛЬЗОВАТЕЛЯ"=:u AND "ID_ИГРЫ"=:g', u=u, g=g)
```

`:u` и `:g` — bind placeholders. Значения передаются отдельно от SQL-текста. Это даёт повторное использование плана и защищает от SQL injection. Нельзя подставлять пользовательскую строку через f-string.

## 9. Снимок игры и многопользовательская работа

GUI запускает `QTimer` с интервалом `POLL_INTERVAL_MS`. `poll()` не начинает второй запрос, пока первый background thread ещё работает. `SnapshotThread` создаёт **свой** `Database()`; connection не передаётся между потоками. После запроса connection закрывается.

`get_game_snapshot` отдаёт шесть `OUT SYS_REFCURSOR`:

- `state` — игра, текущий ход, версия;
- `players` — участники;
- `cells` — статическое поле, только когда `include_static=1`;
- `ownerships` — изменившиеся владения, если версия новая;
- `actions` — только ID новее `last_action_id`;
- `chat` — только ID новее `last_message_id`.

Это polling, а не WebSocket/push: каждый клиент регулярно спрашивает БД. `ВЕРСИЯ_СОСТОЯНИЯ` и last IDs уменьшают объём ответа.

## 10. Реляционная модель

```text
ПОЛЬЗОВАТЕЛИ 1 ──< УЧАСТНИКИ >── 1 ИГРЫ
                           │             │
                           │             ├──< ВЛАДЕНИЯ >── КЛЕТКИ
                           │             ├──< АУКЦИОНЫ >── КЛЕТКИ
                           ├──< СТАВКИ >── АУКЦИОНЫ
                           ├──< ЧАТ
                           └──< ЖУРНАЛ_ДЕЙСТВИЙ >── КЛЕТКИ

КАРТЫ_ШАНСА >── КЛЕТКИ (только для перемещения)
ИГРЫ/УЧАСТНИКИ/АУКЦИОНЫ/ЖУРНАЛ ──> свои таблицы-справочники
```

### Таблицы-справочники

`СТАТУСЫ_ИГР`, `СТАТУСЫ_УЧАСТНИКОВ`, `СТАТУСЫ_АУКЦИОНОВ`, `ТИПЫ_ДЕЙСТВИЙ`, `СОСТОЯНИЯ_ХОДА` заменяют магические строки ссылками. Нельзя поместить в игру статус, которого нет в справочнике.

### Основные

- `ПОЛЬЗОВАТЕЛИ`: аккаунт, login, password hash, registration date.
- `КЛЕТКИ`: одно и то же поле для всех игр; 12 строк.
- `ИГРЫ`: комната/партия, хост, статус, текущий и победивший участник, таймер и версия.
- `УЧАСТНИКИ`: связь «пользователь в конкретной игре». Именно участник имеет balance, position, turn order, status и ready.
- `КАРТЫ_ШАНСА`: варианты random event.
- `ВЛАДЕНИЯ`: состояние собственности для пары game+cell: owner, building count, mortgage.
- `АУКЦИОНЫ`, `СТАВКИ`: шапка аукциона и ответ каждого участника.
- `ЖУРНАЛ_ДЕЙСТВИЙ`: аудит/лента событий.
- `ЧАТ`: messages, sender, time.

## 11. DDL: синтаксис таблиц

Общий шаблон:

```sql
CREATE TABLE table_name (
    id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR2(100 CHAR) NOT NULL,
    parent_id NUMBER,
    created_at DATE DEFAULT SYSDATE NOT NULL,
    CONSTRAINT fk_name FOREIGN KEY (parent_id) REFERENCES parent(id),
    CONSTRAINT uq_name UNIQUE (name),
    CONSTRAINT chk_name CHECK (...)
);
```

- `CREATE TABLE` создаёт объект.
- Двойные кавычки делают кириллический identifier регистрозависимым; его приходится всегда цитировать точно.
- `NUMBER` — число; `NUMBER(1)` — до одной цифры; `NUMBER(2)` — до двух.
- `VARCHAR2(50 CHAR)` — строка до 50 символов, а не байт.
- `DATE` Oracle хранит дату и время до секунд.
- `IDENTITY` — автономер. `BY DEFAULT` разрешает явно передать ID; без этого Oracle его сгенерирует.
- `PRIMARY KEY` — unique + not null identifier; Oracle автоматически создаёт под него unique index.
- `NOT NULL` — значение обязательно.
- `UNIQUE` — нет двух одинаковых значений/комбинаций.
- `DEFAULT` — значение, если столбец пропущен в INSERT.
- `CHECK` — локальное правило. Например, `"ГОТОВ" IN (0,1)` имитирует Boolean, которого в SQL-таблице этой версии Oracle нет.
- `FOREIGN KEY ... REFERENCES` не позволяет ссылаться на несуществующую строку.
- `CONSTRAINT name` даёт правилу имя, чтобы ошибки и ALTER/DROP были понятными.

Круговая ссылка: `УЧАСТНИКИ` ссылаются на `ИГРЫ`, а `ИГРЫ` — на текущего/победившего участника. Поэтому `ИГРЫ` создаётся сначала без двух FK, затем `УЧАСТНИКИ`, затем `ALTER TABLE ... ADD CONSTRAINT` добавляет обратные ссылки.

## 12. DML и SELECT: весь базовый синтаксис

```sql
INSERT INTO t (a, b) VALUES (1, 2);       -- новая строка
UPDATE t SET b = 3 WHERE a = 1;           -- изменить строки
DELETE FROM t WHERE a = 1;                -- удалить строки
SELECT a, b FROM t WHERE a = 1 ORDER BY b;-- прочитать
```

`WHERE` — фильтр. Без `WHERE` UPDATE/DELETE затронет все строки. `ORDER BY x DESC` сортирует по убыванию, `ASC` по возрастанию. `GROUP BY` собирает группы для `COUNT/SUM/MAX`.

```sql
SELECT ...
FROM a
JOIN b ON b.id = a.b_id
LEFT JOIN c ON c.id = a.c_id;
```

`JOIN`/`INNER JOIN` оставляет только совпавшие пары. `LEFT JOIN` сохраняет все строки слева, подставляя NULL при отсутствии пары. Поэтому leaderboard покажет даже игрока без завершённых игр.

Частые конструкции из package body:

- `SELECT ... INTO variable` — в PL/SQL прочитать **ровно одну** строку. 0 даст `NO_DATA_FOUND`, >1 — `TOO_MANY_ROWS`.
- `NVL(x, y)` — y, если x = NULL.
- `COALESCE(a,b,c)` — первое не-NULL.
- `CASE WHEN condition THEN x ELSE y END` — условие внутри SQL.
- `COUNT(*)`, `SUM`, `MAX`, `MIN` — агрегаты.
- `CEIL` — округлить вверх; `ROUND(x,2)` — до 2 знаков.
- `TRIM` — убрать краевые пробелы; Oracle считает пустую строку NULL.
- `SYSDATE` — текущее server time.
- `DBMS_RANDOM.VALUE`, `TRUNC` — random number и отбрасывание дроби; так выбираются dice/card.
- `WITH name AS (SELECT ...)` — CTE, именованный промежуточный результат. Статистика использует `played` и `fav`.
- `ROW_NUMBER() OVER (ORDER BY ...)` — analytic function: нумерует строки; `rn=1` берёт favorite cell.
- `ROWNUM <= 80` — огранить log после внутренней сортировки.
- `MERGE INTO ... WHEN MATCHED THEN UPDATE WHEN NOT MATCHED THEN INSERT` — upsert. Используется для очерёдности/ставки: обновить существующую или вставить новую.

`INSERT ALL ... SELECT 1 FROM dual` из dictionary seed — Oracle-способ вставить много строк. `DUAL` — служебная таблица из одной строки.

## 13. PL/SQL-блоки, procedures и functions

Анонимный блок:

```sql
DECLARE
    v_value NUMBER;
BEGIN
    SELECT ... INTO v_value FROM ...;
    IF v_value > 0 THEN
        ...;
    ELSE
        ...;
    END IF;
EXCEPTION
    WHEN NO_DATA_FOUND THEN ...;
    WHEN OTHERS THEN ...;
END;
/
```

`DECLARE` необязателен, `BEGIN/END` — executable part, `EXCEPTION` — errors. `;` завершает PL/SQL statement. `/` не часть PL/SQL: SQL*Plus понимает его как «отправить накопленный блок Oracle».

Шаблон procedure:

```sql
PROCEDURE do_something (
    p_input  IN NUMBER,
    p_output OUT VARCHAR2,
    p_both   IN OUT NUMBER
) IS
    v_local NUMBER := 0;
BEGIN
    ...;
END do_something;
```

Шаблон function:

```sql
FUNCTION calculate (p_id IN NUMBER) RETURN NUMBER IS
    v_result NUMBER;
BEGIN
    ...;
    RETURN v_result;
END calculate;
```

`p_` и `v_` — соглашение об именах, не keyword. `IN` — вход, `OUT` — выход, `IN OUT` — оба. `:=` — PL/SQL assignment; `=` — comparison. `RETURN` обязателен для function.

### Package

```sql
CREATE OR REPLACE PACKAGE monopoly AS
    -- public declarations
END monopoly;
/
CREATE OR REPLACE PACKAGE BODY monopoly AS
    -- implementations and private helpers
END monopoly;
/
```

Specification — header/API. Body — implementation. `CREATE OR REPLACE` позволяет перекомпилировать. Package даёт namespace (`monopoly.register_user`), инкапсуляцию, единый API и совместные constants.

Константы в spec: `c_start_balance=1200`, start bonus 100, timeout penalty 50, turn 2 minutes, auction 30 seconds, readiness 10 seconds, mortgage interest 10%, bankruptcy reason codes. `CONSTANT` запрещает переприсвать.

## 14. Исключения и бизнес-ошибки

```sql
IF bad_condition THEN
    RAISE_APPLICATION_ERROR(-20001, 'Понятный текст');
END IF;
```

Диапазон `-20000..-20999` предназначен для application errors. Python ловит `oracledb.Error`, делает rollback, достаёт `err.message`, оборачивает в `DatabaseError`. GUI убирает технический `ORA-06512` и показывает текст.

```sql
EXCEPTION
    WHEN DUP_VAL_ON_INDEX THEN ...;
    WHEN NO_DATA_FOUND THEN ...;
    WHEN OTHERS THEN ...;
```

`DUP_VAL_ON_INDEX` — unique violation, `NO_DATA_FOUND` — SELECT INTO не нашёл строку, `OTHERS` — любая оставшаяся ошибка. `RAISE;` повторно выбрасывает текущую.

`01_drop_objects.sql` сознательно глотает errors через `WHEN OTHERS THEN NULL`: если объекта уже нет, installation продолжается. В business logic так делать опасно: можно скрыть bug.

## 15. Курсоры

### `SYS_REFCURSOR`

```sql
FUNCTION list_waiting_games RETURN SYS_REFCURSOR IS
    rc SYS_REFCURSOR;
BEGIN
    OPEN rc FOR SELECT ...;
    RETURN rc;
END;
```

Это weakly typed pointer на result set: форма столбцов определяется запросом. Python обязан прочитать и закрыть его.

### Неявный cursor FOR loop

```sql
FOR r IN (SELECT ... FROM ...) LOOP
    -- r.column_name
END LOOP;
```

Oracle сам открывает, fetch-ит и закрывает cursor. Так обходятся lists of mortgaged/sold properties и tables during drop. Явной схемы `CURSOR c IS ...; OPEN; FETCH; CLOSE;` в package body нет, потому что FOR-loop/ref cursor удобнее.

## 16. Индексы и конкурентность

Шаблон:

```sql
CREATE INDEX ix_name ON table_name (column1, column2);
CREATE UNIQUE INDEX uq_name ON table_name (column1);
```

Индекс ускоряет SELECT/JOIN/ORDER BY, но занимает место и замедляет INSERT/UPDATE/DELETE, потому что его тоже надо менять.

Явные индексы проекта:

- `IX_УЧ_ИГРА` — быстро participants of game.
- `UQ_УЧ_ИГРА_ОЧ` — function-based unique index. `CASE WHEN "ОЧЕРЕДЬ_ХОДА" IS NOT NULL THEN "ID_ИГРЫ" END, "ОЧЕРЕДЬ_ХОДА"` запрещает двум active participants одной game иметь один номер хода, но разрешает много NULL для lobby.
- `IX_ВЛАД_ИГРА` — ownerships by game.
- `IX_АУК_ИГРА` — auctions by game.
- `IX_ЖУРНАЛ_ИГРА(game,time)` — event timeline.
- `IX_ЖУРНАЛ_НОВЫЕ(game,id)` — incremental polling `ID > last_id`.
- `IX_АУК_АКТИВЕН(game,status)` — find current auction.

Кроме них Oracle создаёт unique indexes для primary/unique constraints.

`SELECT ... FOR UPDATE` блокирует найденные rows до commit/rollback. Это критично: два клиента не должны одновременно купить одну улицу, потратить один balance или закрыть один auction. Второй request ждёт first transaction, потом перечитывает state.

## 17. Триггеры: что это и почему их здесь нет

Общий шаблон (учебный, не из этого проекта):

```sql
CREATE OR REPLACE TRIGGER trg_name
BEFORE INSERT OR UPDATE ON table_name
FOR EACH ROW
BEGIN
    :NEW.updated_at := SYSDATE;
END;
/
```

`BEFORE/AFTER` — когда, `INSERT OR UPDATE` — на какие events, `FOR EACH ROW` — один вызов на row, `:NEW`/`:OLD` — новое/старое values. В проекте trigger не объявлен. ID делает `IDENTITY`, даты — `DEFAULT SYSDATE`, log — явный `add_action`, business state — package procedures. Это делает flow видимым и управляемым.

## 18. `NUMBER_LIST`: как передаётся список

```sql
CREATE OR REPLACE TYPE number_list AS TABLE OF NUMBER;
```

Это schema-level nested table type. Python не может просто передать list туда, где PL/SQL ждёт Oracle collection. Поэтому:

```python
type_object = connection.gettype('NUMBER_LIST')
obj = type_object.newobject()
obj.extend([int(x) for x in ids])
```

Затем object идёт в `mortgage_properties`/`resolve_debt`. PL/SQL может использовать `TABLE(p_ids)` в SQL или обходить collection.

## 19. Что делает каждая PL/SQL-подпрограмма

### Account и rooms

- `register_user` — validates и inserts account with hash.
- `authenticate_user` — compares hash and returns user ID.
- `create_game` — validates, inserts game and host participant, returns game ID.
- `list_waiting_games` — rooms cursor с participant counts/password flag.
- `join_game` — locks game, checks status/capacity/password/duplicates, inserts or restores participant.
- `leave_lobby` — removes participant from waiting room and may abandon/reassign host state.
- `abandon_waiting_game` — host abandons room and changes participants.
- `kick_participant` — private body routine for exclusion during readiness.
- `request_start`, `set_ready`, `start_game` — readiness state machine; start assigns order/balance, creates ownership rows and starts timer.

### Reading state

- `participant_game` — private helper participant → game ID.
- `get_game_state`, `get_game_participants`, `get_board_state`, `get_player_properties`, `get_active_auction` — focused ref-cursor reads.
- `get_game_snapshot` — combined incremental six-cursor API for polling.

### Turn and cell

- `roll_and_move` — validates current state, generates dice, moves, awards start, logs and calls cell processing.
- `process_cell` — branches by cell type/owner into chance, purchase, rent, improvement or end state.
- `advance_to_next_player` — chooses next active order cyclically.
- `end_turn` — validates state and advances.
- `buy_property`, `decline_purchase` — buy or turn the free property into auction.
- `calculate_rent` — base price/buildings/color monopoly or utility dice multiplier.
- `pay_rent` — transfers money and enters debt flow if needed.
- `apply_chance` — chooses a random card, changes money/position and processes consequences.
- `owns_full_color_group` — returns 1/0 whether all group streets are owned and unmortgaged.
- `build_house`, `decline_improvement` — buy next level or skip.

### Debt/property

- `sell_buildings` — validates ownership/count and returns sale value.
- `mortgage_properties` — processes Oracle list, checks buildings/owner/mortgage and credits half prices.
- `resolve_debt` — atomically applies selected sales/mortgages and then checks whether debt is covered.
- `enter_debt_or_bankruptcy` — private decision: debt state or immediate bankruptcy.
- `redeem_property` — pays 110% and clears mortgage.
- `return_properties_to_bank` — private reset of bankrupt participant's property.
- `declare_bankruptcy`, `finish_or_continue`, `finish_game` — eliminate participant, return assets and either continue or set winner/final dates.

### Auction

- `start_auction` — creates active auction and changes turn state.
- `make_bid` — validates participant, amount and balance; MERGE stores one current response per player.
- `close_auction` — locks, finds winner, charges, transfers property, or marks failed.

### Timers and exit

- `handle_timeout` — first miss gives penalty/advance; repeat can bankrupt.
- `check_game_timer` — checks readiness, auction, debt and turn deadlines; called during snapshots, so polling drives timeout processing.
- `leave_active_game` — voluntary bankruptcy.
- `disconnect_player` — handles closing/minimizing the client according to game status.

### Chat, log, stats

- `add_action` — central INSERT into log plus state version increment.
- `send_message`, `get_chat`, `get_action_log` — chat/event feed.
- `get_player_stats`, `get_leaderboard`, `get_game_history` — aggregation, win percentage, favorite cell and completed games.

Нюанс защиты: некоторые helper routines объявлены в specification, поэтому технически public, даже если Python их не вызывает. При жёстком API в spec оставляют только client operations, helpers держат только в body.

## 20. Инсталляторы SQL и Python

### `install.sql`

- `SET DEFINE OFF` — SQL*Plus не подставляет `&variables`.
- `SET SERVEROUTPUT ON` — разрешает output `DBMS_OUTPUT`.
- `WHENEVER SQLERROR EXIT SQL.SQLCODE` — shell получит nonzero exit code при SQL error.
- `@file.sql` — выполнить другой script из current directory.
- `PROMPT` — печать text, не SQL.

Порядок важен: drop → tables → referenced dictionaries/cells/cards → collection type → spec → body. Body не скомпилируется без tables/type/spec.

### `install.py`

`ROOT = Path(__file__).resolve().parent` делает paths независимыми от current directory. Generator `statements()` читает lines, пропускает SQL*Plus commands, простой SQL завершает по `;`, PL/SQL/package — по отдельной `/`. `yield` делает его generator: statement-ы отдаются по одному.

После execute инсталлятор смотрит `USER_OBJECTS`, что PACKAGE и PACKAGE BODY имеют `VALID`. При ошибке добавляет file и начало statement. Однако Oracle DDL делает implicit commits, поэтому rollback не может восстановить старую схему после partial failed reinstall.

## 21. Python-синтаксис на этом коде

- `from __future__ import annotations` откладывает evaluation type hints.
- `class Database:` описывает type object; `self` — текущий object.
- `__init__` — constructor, вызывается при `Database()`.
- `def`, parameters, `return` — function definition/result.
- `list[Any] | None` — тип-подсказка: list или None; runtime её сам не enforce-ит.
- `params or []` — если params falsy/None, взять empty list.
- `try/except/finally` — основной code / error handling / unconditional cleanup.
- `raise DatabaseError(...) from exc` сохраняет original cause chain.
- `with` гарантирует cleanup context manager.
- List comprehension `[int(x) for x in ids]` — создать transformed list.
- Dictionary comprehension и `dict(zip(...))` — создать mappings.
- `lambda: self.s.buy(...)` — функция без имени, передаваемая в common `act`.
- `*outputs` распаковывает 6 cursors в argument list; `zip(names, outputs)` идёт парами.
- `hasattr(value, 'getvalue')` поддерживает driver return variants for OUT.
- `if __name__ == '__main__'` — запускать entry point только при direct/module execution, не при import.

Qt использует signal-slot. `button.clicked.connect(self.buy)` регистрирует callback. `QApplication.exec()` запускает event loop: ждёт mouse/keyboard/timer/signal events. `QStackedWidget` хранит login/rooms/lobby/game/finish pages и показывает одну. `QPainter` рисует board в `paintEvent`. `QTimer` даёт polling и local countdown. `QThread` убирает network wait с GUI thread.

## 22. Транзакции: кто делает COMMIT

Пакет в основном не коммитит сам. Граница транзакции у клиента:

```text
callproc
  → several SELECT FOR UPDATE / INSERT / UPDATE
  → success: Python COMMIT
  → Oracle error: Python ROLLBACK
```

Это атомарность: при buy нельзя списать balance, но не передать ownership. Оба changes либо commit, либо rollback.

`callfunc` не коммитит. Для чистых reads это нормально, но нюанс: `check_game_timer` может менять state во время snapshot; именно `snapshot()` поэтому явно коммитит после procedure.

Oracle по умолчанию read-consistent: SELECT видит согласованную версию committed data, а не чужие незавершённые изменения.

## 23. Установочный drop

`EXECUTE IMMEDIATE` выполняет dynamic SQL. Он нужен, потому что DDL нельзя написать как статический PL/SQL statement. Loop берёт only names из жёсткого whitelist в `USER_TABLES`. `||` — concatenation. `CASCADE CONSTRAINTS` удаляет referring constraints, `PURGE` минует recycle bin.

Таблицы дропаются по списку из data dictionary. Package удаляется первым, collection type — с `FORCE`. После этого installation creates clean schema.

## 24. Что говорить на защите

### Краткий рассказ на 2 минуты

> Это client-server application. Oracle Free работает в Docker и слушает 1521; Python через python-oracledb подключается к service FREEPDB1 под user monopoly. Schema состоит из 15 normalized tables, reference integrity задана PK/FK/UNIQUE/CHECK. Вся бизнес-логика находится в PL/SQL package MONOPOLY: Python service вызывает procedures/functions, а GUI только отображает result. Mutations фиксируются COMMIT и откатываются ROLLBACK. SELECT FOR UPDATE защищает concurrent actions. Клиенты по polling забирают incremental snapshot через six ref cursors. Indexes ускоряют поиск по game/status/id. Triggers в schema нет: identity/defaults и explicit package logic их заменяют.

### Типичные вопросы

**Где хранится текущая игра?** В `ИГРЫ`; players/positions/balances — `УЧАСТНИКИ`; property state — `ВЛАДЕНИЯ`.

**Почему user ID и participant ID разные?** User — global account; participant — этот account в одной game с конкретным balance/status/position.

**Почему правила в БД, а не Python?** Все клиенты получают одни атомарные rules; client не может обойти validation.

**Чем procedure от function?** Function имеет `RETURN type` и возвращает value; procedure выполняет action, outputs может дать через OUT.

**Зачем indexes?** Чтобы Oracle не перебирал всю table при typical game filters; unique index ещё и гарантирует turn-order rule.

**Зачем cursors?** Результат SELECT может иметь много rows/columns; ref cursor передаёт его Python потоково.

**Зачем COMMIT в Python?** Client controls transaction boundary: все изменения одного game action фиксируются вместе.

**Есть ли trigger?** Нет. Нужно так и сказать, а не выдумывать.

**Как два окна видят изменения?** Каждое имеет свой connection и регулярно calls snapshot; после commit одного клиента другой получает новую version/actions/messages.

## 25. Слабые места, которые полезно понимать

- Credentials имеют insecure defaults в source/config instructions. Для production secrets не commit-ят.
- SHA-256 password hashing without salt лучше plaintext, но не production-grade password storage.
- Главный connection открыт всё life of window; reconnect/pool нет.
- Polling прост, но creates periodic connections/queries; background snapshot каждый раз открывает новый connection.
- Timers проверяются client polling, а не autonomous server scheduler: если никто не poll-ит, transition может произойти позже.
- Кириллица в quoted identifiers наглядна для lab, но требует exact quotes/register и усложняет tooling.
- Reinstall удаляет data; это development reset, не migration strategy.
- `WINDOWS_DEPLOYMENT.md` упоминает `09_views.sql`, `10_tests.sql`, `network_test` и `.env.example`, но в текущем дереве этих файлов нет. На защите лучше опираться на фактическое repository state.
