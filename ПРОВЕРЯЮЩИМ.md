# Как запустить игру

На каждом компьютере нужны Windows, Python 3.12 x64 и доступ к Oracle. Для установки зависимостей нужен интернет. Распакуйте проект перед запуском.

1. Запустите `1_Подготовить_окружение.bat`. Он создаст `.venv-windows`, установит зависимости и скопирует `.env.example` в `.env`, если такого файла ещё нет.
2. Откройте `.env` в Блокноте и замените параметры подключения:

   ```dotenv
   ORACLE_USER=KS2318_03
   ORACLE_PASSWORD="ВАШ_ПАРОЛЬ_ORACLE"
   ORACLE_DSN="(DESCRIPTION=(ADDRESS=(PROTOCOL=TCP)(HOST=10.22.10.41)(PORT=1521))(CONNECT_DATA=(SID=ORCL)))"
   ```

   Логин, пароль, адрес, порт и SID возьмите из своего рабочего подключения SQL Developer. Значения выше — пример. Если используется Service name, формат DSN: `сервер:порт/имя_сервиса`. Остальные строки `.env` оставьте без изменений. Имя файла должно быть `.env`, а не `.env.txt`.

3. **Только первый участник, один раз:** откройте папку проекта в Проводнике, в адресной строке введите `cmd` и выполните команду установки объектов игры:

   ```bat
   .venv-windows\Scripts\python.exe -m database.install
   ```

   Ожидаемый результат: `Схема установлена. Пакет MONOPOLY: VALID.` Нужен существующий пользователь Oracle с правами `CREATE SESSION`, `CREATE TABLE`, `CREATE TYPE`, `CREATE PROCEDURE` и квотой на таблицы. Если объекты игры уже установлены, этот шаг пропустите. Повторная установка не очищает базу и завершится ошибкой на существующих объектах.

4. Каждый участник запускает `2_Запустить_игру.bat` и регистрирует свой игровой аккаунт. Первый создаёт комнату, остальные присоединяются и нажимают «Я готов».

**Для совместной игры у всех должны быть одинаковые `ORACLE_USER`, `ORACLE_PASSWORD` и `ORACLE_DSN` в `.env`** — подключение к схеме первого участника. Второй участник базу не устанавливает. Игровые логины у участников разные; это не логины Oracle.

Чтобы сменить пользователя Oracle, закройте игру, исправьте `ORACLE_USER` и `ORACLE_PASSWORD` в `.env` (при смене сервера также `ORACLE_DSN`) и снова запустите батник № 2. Для новой пустой схемы сначала выполните команду из шага 3. Данные из прежней схемы автоматически не переносятся. Файлы `connection.json` и `connection_for_player2.json` новым батникам не нужны.

При последующих запусках достаточно батника № 2. Заполненный `.env` содержит пароль: не публикуйте его в Git или общем архиве.
