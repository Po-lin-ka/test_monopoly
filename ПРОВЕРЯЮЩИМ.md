# Запуск для двух проверяющих

Обоим передаётся один архив `Передать_проверяющим.zip`. Распакуйте его в обычную папку, доступную для записи. Запускать из окна архива нельзя.

## Что должно быть на рабочих местах

- Windows и Python 3.12 x64 (как на учебном рабочем столе). Батник проверяет наличие Python.
- Доступ к серверу Oracle с обоих компьютеров и существующая учётная запись первого участника с правами создавать таблицы, типы и пакеты, а также квотой на таблицы.
- Интернет для первой установки Python-зависимостей. Последующие запуски используют готовое окружение `.venv-windows`.

Батники сами создают окружение, устанавливают зависимости, проверяют подключение и открывают игру. Oracle, учётную запись на сервере, Python и доступ к сети предоставляет учебное рабочее место; батники не могут автоматически получить административные права или неизвестный пароль базы.

## Первый участник — установить таблицы и играть

1. Дважды щёлкните `1_Создать_базу_и_играть.bat`.
2. При первом запуске введите логин и пароль **Oracle**, адрес сервера, порт и SID / Service name из работающего подключения SQL Developer. Пароль вводится скрыто. Предложенные значения `10.22.10.41`, `1521`, `SID ORCL` взяты из вузовской инструкции; если у вас другие параметры, введите свои.
3. Дождитесь установки и окна входа в игру. SQL вручную выполнять не нужно.
4. Передайте второму участнику появившийся рядом с батниками файл `connection_for_player2.json`.
5. Зарегистрируйте в окне игры игровой аккаунт и войдите.

Файл подключения содержит пароль Oracle и передаётся только второму проверяющему лично. В исходном архиве его нет. Первый батник устанавливает объекты в существующей схеме Oracle, а не устанавливает сервер Oracle на компьютер. Первый компьютер не обязан оставаться включённым, если сервер базы расположен отдельно.

## Второй участник — подключиться и играть

1. Получите `connection_for_player2.json` от первого участника и положите его в свою распакованную папку рядом с батниками.
2. Дважды щёлкните `2_Подключиться_и_играть.bat`.
3. Дождитесь окна игры и зарегистрируйте **другой игровой аккаунт**.
4. Первый игрок создаёт комнату, второй выбирает её и нажимает «Присоединиться». Оба нажимают «Я готов»; через 10 секунд начинается партия.

Второй использует ту же учётную запись Oracle из файла, но другой игровой логин. Если указать свою отдельную схему Oracle, общей комнаты не будет. Настройки сохраняются автоматически, `.env` вручную редактировать не требуется.

## Последующие запуски

Каждый запускает свой прежний батник. Исправная база используется повторно; аккаунты и результаты сохраняются. Второй батник никогда не устанавливает схему. Первый устанавливает её только при отсутствии объектов игры. При конфликте имён, неполной установке или невалидном пакете автоматическое удаление не выполняется.

Если установка прервалась, сохраните текст ошибки. Oracle фиксирует DDL по мере выполнения: частично созданные таблицы сами не откатятся. Для нового чистого развёртывания нужна другая свободная схема либо разбор ошибки с администратором; повторный запуск не стирает существующие данные.

## Если запуск не удался

| Сообщение / ситуация | Что сделать |
|---|---|
| Нет Python 3.12 x64 | Установить Python 3.12 с python.org, включив Add python.exe to PATH; на учебном ПК без прав — обратиться к администратору. |
| Ошибка установки зависимостей | Проверить интернет; сохранить сообщение из консоли. |
| Нет файла подключения у второго | Положить полученный JSON рядом с батником № 2. |
| Неверный пароль / адрес Oracle | У первого переименовать `connection.json` и `connection_for_player2.json`, заново запустить батник № 1 и ввести верные параметры; передать новый файл второму. |
| Домашний компьютер не видит вузовскую базу | Запустить игру на учебном удалённом рабочем столе либо использовать предусмотренный вузом доступ к сети. |
| Недостаточно прав / квоты | Передать сообщение администратору Oracle. Батник не создаёт пользователей и не выдаёт себе права. |
| Несовместимый сервер / аутентификация Oracle | Сохранить полный код ошибки драйвера для настройки подключения администратором. |
| Неполная или несовместимая схема | Не удалять таблицы наугад; сохранить ошибку и проверить установку в свободной схеме. |
| Другой игрок не видит комнату | Передать актуальный файл подключения и перезапустить второй клиент; убедиться, что комната ещё ожидает участников. |

Проверки игры и бланк результатов находятся в `ПИМ_Упрощённая_монополия.pdf`; редактируемый вариант — одноимённый DOCX. ФИО и группа на титуле оставлены для заполнения.
