# Запуск Monopoly Lite в вузе

Инструкция для групп КС-23-03 и КС-23-18: перенос проекта, установка базы, запуск Python и совместная игра.

## 1. Какие подключения используются

По памятке вуза для этих групп:

| Назначение | Значение |
|---|---|
| Удалённый рабочий стол | `10.24.177.151` |
| Сервер Oracle (Hostname) | `10.22.10.41` |
| SID | `ORCL` |
| Порт Oracle | Предположительно `1521`; сверить с работающим подключением SQL Developer |
| Пользователь Oracle | Ваш пользователь `КС2318_03`; точное написание скопировать из SQL Developer |

В верхней части памятки приведён пример для другого подключения с сервером `10.22.10.64`. Для вашей группы ориентируйтесь на её отдельный блок и параметры своего работающего подключения.

Адрес удалённого рабочего стола и адрес Oracle — разные адреса. В настройках игры нужен адрес Oracle.

Игра работает так: каждое окно Python подключается к общей схеме Oracle. Отдельный сервер Python не требуется. SQL Developer нужен для просмотра и проверки базы; держать его открытым во время игры необязательно.

## 2. Перенести файлы

1. На своём компьютере упакуйте проект в ZIP.
2. Подключитесь к удалённому рабочему столу вуза.
3. Перенесите ZIP через копирование файлов, если оно разрешено, либо другим разрешённым в вузе способом.
4. Распакуйте архив, например в `Документы\Monopoly`. Не запускайте проект прямо из архива.

Нужны следующие файлы и папки:

```text
Monopoly/
    app/                         целиком, включая assets
    database/                    целиком
    requirements.txt
    .env.example
    rebuild_and_run_windows.bat
    УЧЕБНИК_ПО_ПРОЕКТУ.md
    ЗАПУСК_В_ВУЗЕ.md
```

Папки `.git` и `.venv` переносить не требуется. Окружение Python создаётся на целевом компьютере. Файл `.env` создайте там по инструкции ниже; если перенесли старый, замените домашние настройки вузовскими.

Все дальнейшие команды выполняйте на удалённом рабочем столе вуза, в папке проекта.

## 3. Настроить Oracle в файле .env

Откройте свойства работающего подключения в SQL Developer и проверьте Username, Hostname, Port и выбранный вариант SID. Название подключения в списке слева не является именем пользователя или SID.

Скопируйте `.env.example` в файл `.env` в корне проекта. Включите отображение расширений в Проводнике: имя должно быть `.env`, а не `.env.txt`.

Пример для параметров вашей группы:

```dotenv
ORACLE_USER=ТОЧНЫЙ_ЛОГИН_ИЗ_SQL_DEVELOPER
ORACLE_PASSWORD="ВАШ_ПАРОЛЬ_ORACLE"
ORACLE_DSN="(DESCRIPTION=(ADDRESS=(PROTOCOL=TCP)(HOST=10.22.10.41)(PORT=1521))(CONNECT_DATA=(SID=ORCL)))"
POLL_INTERVAL_MS=2000
CONNECT_TIMEOUT_SECONDS=5
CALL_TIMEOUT_MS=5000
```

Замените логин и пароль своими значениями. Порт `1521` сверьте с SQL Developer. Если в работающем подключении другие параметры, используйте их.

Латинские `KC` и русские `КС` — разные символы, поэтому логин лучше скопировать. Пароль нужен от Oracle, а не от удалённого рабочего стола. Не публикуйте заполненный `.env` в Git: он уже исключён через `.gitignore`.

Если в SQL Developer выбран **Service name**, а не SID, используйте другой формат:

```dotenv
ORACLE_DSN=ИМЯ_СЕРВЕРА:ПОРТ/ИМЯ_СЕРВИСА
```

SID нельзя автоматически подставлять вместо Service name. Форматы описаны в [документации python-oracledb](https://python-oracledb.readthedocs.io/en/latest/user_guide/connection_handling.html).

## 4. Подготовить Python

В Проводнике откройте папку проекта, в адресной строке напишите `cmd` и нажмите Enter. Откроется командная строка в нужной папке. Команды ниже рассчитаны на CMD.

Проверьте наличие Python:

```bat
py -3 --version
```

Если Python найден, выполните по очереди:

```bat
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для скачивания зависимостей нужен доступ к интернету. Дождитесь успешного завершения установки.

Если команда `py` не найдена, проверьте:

```bat
python --version
```

Если эта команда показывает установленный Python 3, окружение можно создать так:

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если Python отсутствует, установите его на удалённом компьютере, если это разрешено. При ограничениях установки обратитесь к администратору. Если установка зависимостей сообщает о несовместимой версии Python, сохраните полный текст ошибки: версию нужно подобрать под зависимости из `requirements.txt`.

## 5. Один раз создать таблицы и пакет игры

**Команда полной установки сначала удаляет прежние объекты игры с именами, перечисленными в `database/01_drop_objects.sql`, в выбранной схеме.** Существующие игровые партии и аккаунты будут потеряны. Если в учебной схеме уже есть одноимённые таблицы, например `ПОЛЬЗОВАТЕЛИ`, сначала проверьте конфликт. Не выполняйте полную установку перед каждой демонстрацией.

После настройки `.env` и установки зависимостей выполните:

```bat
.venv\Scripts\python.exe -m database.install
```

Скрипт подключится под пользователем из `.env`, создаст таблицы, заполнит справочники, клетки и карты, создаст тип и пакет `MONOPOLY`. Отдельного пользователя Oracle создавать не нужно. Вручную запускать каждый SQL-файл в SQL Developer тоже не требуется.

Ожидаемый результат:

```text
Схема установлена. Пакет MONOPOLY: VALID.
```

В SQL Developer под тем же пользователем можно выполнить:

```sql
SELECT object_type, status
FROM user_objects
WHERE object_name = 'MONOPOLY';
```

Должны быть строки `PACKAGE` и `PACKAGE BODY` со статусом `VALID`.

Дополнительная проверка начальных данных:

```sql
SELECT COUNT(*) FROM "КЛЕТКИ";
SELECT COUNT(*) FROM "КАРТЫ_ШАНСА";
```

Ожидаются 12 клеток и 10 карт. Обновите список таблиц в SQL Developer, если новые объекты не появились сразу.

Если установка завершилась ошибкой, сохраните весь текст из CMD. Успешное подключение SQL Developer само по себе не подтверждает наличие прав на создание таблиц, типов и пакетов.

## 6. Запустить игру

В CMD из папки проекта выполните:

```bat
.venv\Scripts\python.exe -m app.main
```

В окне игры нажмите «Зарегистрироваться» и создайте игровой аккаунт, например `polina`.

Пользователь Oracle и игровой аккаунт — разные сущности. Приложение подключается к схеме через `.env`, а игровой логин вы вводите в окне игры. Не вводите туда пароль Oracle.

При следующих запусках нужна только эта команда. Повторно создавать базу и устанавливать зависимости не требуется, пока окружение исправно и зависимости не изменились.

### Что делает батник

`rebuild_and_run_windows.bat` удаляет старую `.venv`, создаёт новую, устанавливает зависимости и запускает игру. Если `.env` отсутствует, он копирует шаблон `.env.example`, в котором ещё нет ваших вузовских параметров.

Батник **не устанавливает схему Oracle**. Для первой установки используйте шаги выше. Для обычного запуска удобнее команда `.venv\Scripts\python.exe -m app.main`: она не пересоздаёт окружение и не скачивает зависимости. Перед запуском батника закройте все окна игры, использующие это окружение.

## 7. Проверить игру в двух окнах

1. Запустите игру и зарегистрируйте аккаунт `player1`.
2. Откройте вторую CMD в той же папке и ещё раз выполните `.venv\Scripts\python.exe -m app.main`.
3. Во втором окне зарегистрируйте другой аккаунт — `player2`.
4. Первый игрок создаёт комнату.
5. Второй выбирает её в списке и нажимает «Присоединиться». Если комната защищена, вводит её пароль.
6. Оба игрока отмечают готовность. После готовности всех начинается отсчёт 10 секунд.
7. Проверьте, что оба окна показывают одну партию: отправьте сообщение в чат, сделайте ход, купите свободную клетку при попадании на неё и проверьте обновление состояния у второго игрока.

Для этой проверки достаточно одного удалённого рабочего стола. Используйте разные игровые аккаунты.

## 8. Как подключаться другим игрокам

В текущей версии все экземпляры приложения должны использовать **одну и ту же схему Oracle** с установленной игрой.

У каждого участника должны быть:

- копия проекта на компьютере, откуда доступен сервер Oracle;
- Python и зависимости в собственном окружении `.venv`;
- одинаковые `ORACLE_USER`, `ORACLE_PASSWORD` и `ORACLE_DSN` в `.env`, указывающие на общую схему игры;
- отдельный игровой аккаунт, зарегистрированный через окно приложения.

Остальные участники выполняют подготовку Python и запускают приложение:

```bat
.venv\Scripts\python.exe -m app.main
```

**Другие игроки не выполняют `database.install`**: общая схема уже создана, повторная установка удалит данные игры.

Если вы установили игру под `КС2318_03`, а другой студент укажет в `.env` своего пользователя `КС2318_04`, приложение будет искать объекты в его собственной схеме. Ваши комнаты в текущей реализации он так не увидит. Работа через разные учётные записи Oracle потребует отдельной настройки прав и доработки приложения. Общую учётную запись базы используйте в согласованном учебном окружении; не распространяйте пароль вместе с публичным архивом или репозиторием.

Учётные записи входа в удалённый рабочий стол могут различаться: параметры Oracle приложение берёт из `.env`.

Начните с запуска у участников внутри удалённой среды вуза, где Oracle доступна. Домашний Python сможет подключиться только при наличии сетевого доступа к вузовской базе, например через предусмотренный вузом VPN. Вход через удалённый рабочий стол сам по себе не открывает домашнему Python доступ к Oracle.

## 9. Если что-то не работает

| Проблема | Что проверить |
|---|---|
| `py` не найден | Выполнить `python --version`; проверить установку Python |
| Не устанавливаются зависимости | Полный текст ошибки, версию Python, доступ к интернету и права на папку |
| Не удаётся подключиться к Oracle | Значения `.env`, доступность базы с этого компьютера, SID/Service name, точность логина и пароля |
| Ошибка о неподдерживаемой версии Oracle или режиме драйвера | Сохранить полный код ошибки и уточнить версию Oracle; текущий код использует Thin mode, может потребоваться адаптация |
| Не создаются объекты | Полный текст ошибки установки, права пользователя и квоту на таблицы |
| Пакет имеет статус `INVALID` | Посмотреть `SELECT type, line, position, text FROM user_errors WHERE name = 'MONOPOLY' ORDER BY type, line` |
| Другой игрок не видит комнату | Одинаковы ли сервер и пользователь Oracle у обоих; создана ли комната |
| После изменения `.env` поведение прежнее | Закрыть и заново запустить приложение |

Для повторного показа: войти на удалённый рабочий стол, открыть CMD в папке проекта, выполнить `.venv\Scripts\python.exe -m app.main`, войти в игровой аккаунт. Полную установку базы повторять не нужно.
