# Игра на удалённых рабочих столах в вузе

Учётка Windows `KS2318_XX`, пользователь Oracle и логин внутри игры — три разные учётные записи. Их имена могут совпадать, но приложение не связывает их автоматически.

Для демонстрации все клиенты могут подключаться под одним владельцем схемы Oracle. Тогда раздавать `GRANT` другим студентам не требуется: каждое соединение уже работает с правами владельца. Внутри приложения каждый создаёт отдельный игровой логин. Это модель доверенных учебных клиентов: реквизиты владельца дают также прямой доступ к таблицам.

1. Возьми параметры своего рабочего подключения Oracle из SQL Developer: пользователь базы, пароль, hostname, порт и service name. Адрес удалённого рабочего стола `10.22.10.41` не обязательно является адресом Oracle. Учётка Windows не обязательно подходит для базы.
2. В своей схеме один раз установи проект командой `python -m database.install` из корня проекта с настроенным `.env`. Эта команда удаляет прежние игровые таблицы: для уже установленной базы её повторять не нужно.
3. Передай студентам папку `app`, `requirements.txt` и одинаковый настроенный `.env`. Виртуальное окружение `.venv` со своего компьютера не копируй.
4. На каждом рабочем столе открой терминал в папке проекта и выполни:

```powershell
py -3 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m app.main
```

При следующих запусках нужна только последняя команда. Если Python или доступ к установке зависимостей отсутствует, окружение заранее готовит администратор.

Пример структуры `.env` (значения-заглушки заменить):

```dotenv
ORACLE_USER=ВЛАДЕЛЕЦ_СХЕМЫ_ИГРЫ
ORACLE_PASSWORD=ПАРОЛЬ_ORACLE
ORACLE_DSN=ХОСТ_ORACLE:ПОРТ/ИМЯ_СЕРВИСА
POLL_INTERVAL_MS=2000
```

Здесь нет имени игрового пользователя. После запуска каждый нажимает регистрацию, выбирает собственные логин и пароль. Один создаёт комнату, остальные видят её в общем списке и присоединяются. У всех должна быть одна база и одна схема; отдельная установка таблиц на каждой студенческой учётке разделит игроков по независимым играм.

Для точной настройки вузовского `.env` нужны параметры рабочего подключения к Oracle, а не пароль от удалённого рабочего стола. Пароли в переписку присылать не нужно.

SQL*Plus для этого сценария не нужен: `database/install.sql` — альтернативный установщик; Python использует `database/install.py`, который проверяет компиляцию пакета. Docker на рабочих столах тоже не нужен, если общая Oracle уже доступна.

Формат DSN описан в [документации python-oracledb](https://python-oracledb.readthedocs.io/en/latest/user_guide/connection_handling.html).
